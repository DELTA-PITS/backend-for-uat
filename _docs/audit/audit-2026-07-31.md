# Audit Codebase — Backend "trustmark" (PITS Backend)

**Tanggal audit**: 2026-07-31
**Lokasi**: `backend-for-uat/`
**Konteks project**: Backend untuk *Public Information Trust System* (PITS) — proof-of-concept (PoC) registrasi dokumen (hash SHA-256 + anchoring ke blockchain lokal Anvil) dan verifikasi publik integritas dokumen. Stack: FastAPI, PostgreSQL, Keycloak (OIDC/JWT), Web3/Anvil, SQLAlchemy, Dynaconf. README menyatakan eksplisit ini **PoC**, bukan produksi.

Catatan: `pyproject.toml` mendeskripsikan project dengan teks generik "trustmark ... FAIR principles" yang tidak sesuai fungsi aktual (notarization blockchain) — metadata project tidak pernah diperbarui.

## 1. Struktur & Arsitektur

Struktur `src/trustmark/`:
```
api/v1/        documents.py (terisi), exports.py, inventor.py, status.py, verification.py, metrics.py (health check duplikat)
infra/         auth/keycloak.py, blockchain_connector.py, commons.py, db.py, hash_engine.py, cache.py, hash_generator.py, reports.py
models/        documents.py (Pydantic, tidak dipakai)
registry/      models.py (SQLAlchemy ORM)
services/      etherum_connector.py, github_connector.py, graphdb_connector.py, x_connector.py
utils/         helper (file kosong tanpa ekstensi .py)
```

**Medium — Banyak file kosong/dead code yang membingungkan arsitektur.**
File berikut 0 byte dan tidak direferensikan di manapun (dikonfirmasi via grep menyeluruh):
`api/v1/{exports,inventor,status,verification}.py`, `infra/{cache,reports,hash_generator}.py`, `services/{etherum_connector,github_connector,graphdb_connector,x_connector}.py`, `utils/helper`, `models/documents.py` (model Pydantic `Document`/`Provenance` tidak dipakai — endpoint register/verify memakai `UploadFile` mentah).

Ini menunjukkan arsitektur "direncanakan lebih besar" (multi-connector GitHub/X/GraphDB/Ethereum) namun implementasi aktual jauh lebih sempit — hanya `documents.py` + `keycloak.py` + `blockchain_connector.py` yang aktif. Scaffolding sisa ini sebaiknya dihapus atau diberi catatan "not implemented".

**Low — Duplikasi endpoint health check.**
`main.py:70-72` mendefinisikan `GET /health` langsung di app, sementara `api/v1/metrics.py:12-20` juga mendefinisikan `GET /health` (dengan `response_model` + docstring OpenAPI) di prefix `/api/v1`. Dua endpoint health terpisah, tidak konsisten — versi `main.py` tidak punya dokumentasi Swagger.

Untuk kode yang memang dipakai (auth di `infra/auth`, db di `infra/db.py`, hashing di `infra/hash_engine.py`, business logic di `api/v1/documents.py`), separation of concerns cukup rapi.

## 2. Security

### Critical — Secret/private key ter-commit ke git history
`docker/.env.save` ter-tracked di git (commit `a70d53b "Initial stakeholder UAT release"`), berisi:
- `docker/.env.save:9` `POSTGRES_PASSWORD=trustmark`
- `docker/.env.save:14` `KEYCLOAK_PASS=admin`
- `docker/.env.save:19` `BLOCKCHAIN_PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80`

`.gitignore:211` hanya meng-ignore `docker/.env`, bukan `docker/.env.save` — file `.save` lolos. Isinya sama dengan `docker/.env.example` (private key adalah akun deterministik publik Anvil #0, bukan rahasia sungguhan), tapi **pola kebocorannya tetap masalah nyata**: kebiasaan file `.env.save`/backup yang lolos gitignore berisiko tinggi kalau suatu saat berisi kredensial produksi sungguhan.

**Rekomendasi**: hapus dari working tree & riwayat git (`git filter-repo`/BFG), ganti pola `.gitignore` jadi `docker/.env*` (bukan exact-match).

### High — Bypass otentikasi lewat `TEST_MODE`, wiring rapuh
`main.py:99-113`:
```python
async def override_get_current_principal():
    return Principal(sub="test-user", ..., roles={"publisher"}, claims={})

if __name__ == "__main__":
    if os.environ.get("TEST_MODE", "false").lower() == "true":
        app.dependency_overrides[get_current_principal] = override_get_current_principal
```
- Satu env var `TEST_MODE=True` menonaktifkan total verifikasi JWT/role untuk semua endpoint auth. `.github/docker/.env.example:17` men-default `TEST_MODE=True` untuk CI/E2E. Tidak ada guard tambahan (mis. larangan `TEST_MODE=True` bila `ENVIRONMENT=production`).
- **Bug tersembunyi**: override hanya terpasang di blok `if __name__ == "__main__"` — hanya aktif kalau app dijalankan `python -m trustmark.main` (sesuai `docker/Dockerfile:50`). Kalau dijalankan via entry-point `start = "trustmark.main:main"` (`pyproject.toml:33`) atau `uvicorn trustmark.main:app`, blok ini **tidak pernah dieksekusi** — `TEST_MODE=True` diam-diam tidak berefek.

### Medium — CORS default permisif untuk method/header
`main.py:55-61`: `allow_methods=["*"]`, `allow_headers=["*"]`, `allow_credentials=True`; origin dari env `CORS_ALLOW_ORIGINS` (default `http://localhost:3000`) sudah dibatasi, tapi method/header wildcard lebih permisif dari kebutuhan aktual (hanya GET/POST dipakai).

### Low/Info — `python-jose` untuk verifikasi JWT
`infra/auth/keycloak.py:7` — historis punya isu algorithm confusion, kurang aktif dibanding `PyJWT`. Mitigasi sudah baik: `algorithms=["RS256", "PS256"]` hardcoded (`keycloak.py:134`), `verify_iss`/`verify_aud`/`verify_exp` eksplisit True (`keycloak.py:138-142`) — risiko `alg: none` classic sudah tertutup.

### Positif (bukan gap)
- Autentikasi & otorisasi solid: `keycloak.py` verifikasi JWT penuh via JWKS (cache TTL 3600s, refresh-on-kid-miss di `keycloak.py:104-125`), validasi issuer/audience/expiry, role-based access via `require_roles("publisher")` konsisten (`documents.py:51,81`).
- Validasi upload manual cukup baik: cek file kosong (`documents.py:29-30`), cek ukuran maksimum via `MAX_UPLOAD_BYTES` (`documents.py:31-32`), validasi format hash SHA-256 ketat via whitelist hex (`documents.py:112`) sebelum query DB.
- Tidak ada hardcoded secret di kode `.py` — semua kredensial dari env/settings, kecuali kasus `docker/.env.save` di atas.

- `test_hash_engine.py` — 7 test, termasuk edge case tipe salah.
- `test_blockchain_connector.py` — ~9 test dengan mock Web3/Account.

**High — Gap besar cakupan test**: tidak ada test untuk `api/v1/documents.py` (register/verify/records — tidak ada integration test `TestClient`/`httpx`), dan **tidak ada test untuk `infra/auth/keycloak.py`** — komponen keamanan paling sensitif. Tidak ada test untuk `registry/models.py`, `db.py`, `commons.py`. Tidak ada `conftest.py`.

**Bug di Locust test** (Low): `tests/locust/locustfiles/verify.py:32,35`:

## 4. Konfigurasi & Deployment

- `docker/Dockerfile`: base `python:3.12.8-bookworm`, `apt-get upgrade -y && dist-upgrade -y` (baris 9-14, build tidak reproducible), install via `uv sync --frozen` (baik), jalan non-root user `akmi` (baik).
- Komentar mencurigakan `docker/Dockerfile:36`: `#Temporary, will be removed later` di atas `COPY conf ./conf` — config di-bake ke image, sementara `.github/docker/Dockerfile` mount `conf/` sebagai volume. Dua strategi berbeda, technical debt tak pernah ditindaklanjuti.
- **Medium** — Tidak ada healthcheck untuk service `trustmark-app` di `docker/docker-compose.yml:58-85` (postgres & anvil punya, app tidak, padahal endpoint `/health` sudah ada). Versi `.github/docker/docker-compose.yml` justru punya ini.
- Duplikasi hampir total antara `docker/` dan `.github/docker/` (Dockerfile + compose + .env.example) dengan perbedaan halus (path, healthcheck, root vs non-root, ada/tidaknya service anvil) — rawan drift.
- **Medium** — `conf/settings.toml` hanya satu section `[default]` walau Dynaconf diinisialisasi `environments=True` (`infra/commons.py:15-20`) — fitur environment-switching (dev/staging/prod) tidak dimanfaatkan; semua "environment" bergantung sepenuhnya pada file `.env` Docker Compose berbeda.
- `conf/settings.toml:2` hardcode `log_level = 10` (DEBUG) untuk semua environment.
- `conf/settings.toml:1,4` masih pakai nama lama: `ptis.log`, `pits.db` — sisa rename yang tidak konsisten.
- README mengakui eksplisit: tidak ada migrasi skema database (Alembic dsb.) — dikonfirmasi tidak ada file migrasi di repo. Disclosed untuk PoC, tapi jadi gap nyata jika dilanjutkan.

## 5. Error Handling & Logging

- Logging ke **file saja** (`main.py:66-68`, `logging.basicConfig(filename=...)`), bukan stdout — buruk untuk container/K8s yang biasanya mengumpulkan log lewat stdout. Tidak ada rotating file handler — file log tumbuh tanpa batas.
- `main.py:33-34` masih ada `print("====== start up==========")` dan `print(emoji.emojize(":thumbs_up:"))` di lifespan handler — debug statement produksi. Dependency `emoji` (`pyproject.toml:24`) tampaknya hanya dipakai untuk ini — tidak proporsional.
- Exception handling di `blockchain_connector.py`/`keycloak.py` konsisten pakai `HTTPException` dengan status code wajar.
- Tidak ada global exception handler (`@app.exception_handler`) di `main.py` untuk exception tak terduga — response error di luar yang sudah di-try/except akan default 500 tanpa format konsisten.

## 6. Code Quality

- **Medium** — `ruff` terdaftar di `[project.dependencies]` (`pyproject.toml:29`), bukan dev-dependency — ikut ter-install di image produksi (`uv sync --frozen`). Salah kategorisasi.
- Tidak ada konfigurasi `[tool.ruff]`, `[tool.mypy]`, atau `[tool.black]` — ruff jalan default rule set, tidak ada type checker dikonfigurasi meski type hints dipakai cukup konsisten.
- Dependency `sqlalchemy-orm>=1.2.10` (`pyproject.toml:26`, resolved versi 1.2.10 dari 2023) — package terpisah membingungkan; SQLAlchemy 2.x sudah include ORM native, tidak butuh package tambahan ini. Kemungkinan salah tambah dependency.
- Docstring hanya lengkap di `main.py:lifespan` dan `commons.py:project_details` — mayoritas fungsi lain (`documents.py`, `keycloak.py`, `blockchain_connector.py`) tanpa docstring.

## 7. Dokumentasi

- `README.md` (root) — dokumentasi terbaik di repo: tujuan, struktur, cara deploy lokal, tabel endpoint + auth requirement, limitasi PoC eksplisit.
- `src/trustmark/infra/README.md` — dokumentasi kecil modul `BlockchainConnector`, cukup jelas.
- Tidak ada folder `_docs/` sebelumnya (baru dibuat lewat audit ini), tidak ada ADR, diagram, atau dokumen requirement formal.
- OpenAPI/Swagger aktif (`/docs`), tapi endpoint `documents.py` (register/verify/records) **tidak punya `summary`/`description`/`response_model`** — kontras dengan `metrics.py` yang rapi. Dokumentasi Swagger untuk endpoint paling penting akan tampil minim.

## Rekomendasi Tindak Lanjut (urutan prioritas)

1. Hapus `docker/.env.save` dari git (working tree + history), perbaiki pola `.gitignore`.
2. Perbaiki wiring `TEST_MODE` bypass agar konsisten terlepas dari cara start aplikasi, dan tambahkan guard agar tidak bisa aktif di `ENVIRONMENT=production`.
3. Aktifkan kembali CI minimal (lint + unit test) sebelum lanjut ke tahap berikutnya dari PoC.
4. Tambah test integrasi untuk `api/v1/documents.py` dan test untuk `infra/auth/keycloak.py`.
5. Bersihkan dead code (file 0 byte) atau beri catatan jelas "not implemented, planned for future".
6. Perbaiki bug assertion di `tests/locust/locustfiles/verify.py`.
7. Rapikan duplikasi `docker/` vs `.github/docker/`, tambahkan healthcheck app di compose lokal.
8. Pindahkan `ruff` ke dev-dependency, tambahkan konfigurasi `[tool.ruff]`, evaluasi kebutuhan `sqlalchemy-orm`.
